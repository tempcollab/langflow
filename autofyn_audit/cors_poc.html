  VULN-009: CORS reflects ANY origin with credentials: true

When a logged-in Langflow user visits this page and clicks the button, their browser sends their session cookies to the Langflow server via a credentialed cross-origin fetch(). The server executes the payload and returns the result. Because CORS reflects this origin, the browser allows this page to read the full response.

How this works (technical)

Langflow's CORS middleware reflects whatever Origin header the browser sends back in access-control-allow-origin, combined with access-control-allow-credentials: true. This means:

  • The browser performs a preflight (OPTIONS) -- Langflow approves it.
  • The browser sends the POST with session cookies attached.
  • The server executes the code payload via exec() inside prepare_global_scope().
  • Because the CORS origin was reflected, the browser allows this page to read the full JSON response -- including RCE output in data.display_name.

The payload uses only ast.Assign nodes -- no ast.Try, ast.Expr, ast.If, or ast.With -- because Langflow's prepare_global_scope() silently drops those node types.

Attacker requirement: Zero Langflow credentials.
Victim requirement: Be logged into Langflow and visit this page.
